Algorithm Description, Role of Keys & Scheme Comparison

  • Main Steps & Role of Keys in the Toy ECC Scheme (ECIES / ElGamal Hybrid over F₁₇):
    1. Key Generation: The receiver selects a secret scalar Private Key d ∈ [1, 17] and computes the Public Key Q = dG on the curve. Q is published openly; d is kept secret for decryption.
    2. Encryption: For each character block m[i], the sender chooses a fresh per-block Ephemeral Key kᵢ ∈ [1, 17] and computes two curve points: the public ephemeral point Rᵢ = kᵢG and the shared secret point Sᵢ = kᵢQ. Using a key derivation mask from coordinates (Sᵢ.x, Sᵢ.y), the sender masks the character: cᵢ = (m[i] + mask(Sᵢ)) mod 256. The transmitted ciphertext consists of pairs (Rᵢ, cᵢ).
    3. Decryption: The receiver uses their Private Key d to compute S'ᵢ = d · Rᵢ. By associativity/commutativity of scalar multiplication, d(kᵢG) = kᵢ(dG) = kᵢQ = Sᵢ. The receiver reconstructs the exact same shared point Sᵢ and recovers m[i] = (cᵢ - mask(S'ᵢ)) mod 256.
Dimension Caesar Cipher Toy ECC Scheme (secp256k1 mod 17)
Encryption & Decryption Procedure Symmetric & Deterministic: Uses identical key k for both encryption E(x) = (x + k) mod 26 and decryption D(y) = (y - k) mod 26. Identical plaintext letters always map to identical ciphertext letters. Asymmetric & Probabilistic: Encrypts with public point Q = dG and fresh ephemeral scalars kᵢ; decrypts with private scalar d via elliptic curve point addition over F₁₇. Identical plaintext letters produce different ciphertexts.
Key Space 26 keys (only 25 non-trivial shifts). Trivial to exhaustively search by hand or computer. Restricted Toy Space: 17 keys (subgroup order n = 18 for p = 17). In real secp256k1, the key space is ≈ 2²⁵⁶ ≈ 1.15 × 10⁷⁷.
Statistical Properties Statistical Invariance (Zero Diffusion): Letter frequencies, double letters, and word patterns are completely preserved—the histogram is merely shifted cyclically by k positions. Confusion & Diffusion: Non-linear point additions and rotating ephemeral keys flatten the output distribution, hiding single-letter frequencies of the underlying natural language.

Discussion: Algorithm Design, Effectiveness, Limitations & Alternatives

  • Algorithm Design (Chi-Squared Goodness-of-Fit): From the reference English corpus, we extract the relative frequency Pᵢ of each letter i ∈ {A..Z}. For each candidate shift g ∈ {0..25}, we decrypt the ciphertext of length N, count the observed letter occurrences Oᵢ, and compare them against the expected counts Eᵢ = N · Pᵢ:
    χ²(g) = ∑ (Oᵢ - Eᵢ)² / Eᵢ. The candidate g minimizing χ²(g) is selected as the recovered key.
  • Effectiveness & Limitations Across Ciphertext Lengths:
    • Long & Medium Texts (≥ 30 letters): By the Law of Large Numbers, the empirical distribution converges rapidly to the corpus profile, yielding 100% accuracy.
    • Very Short Texts (< 10 letters, e.g. "Jazzy" or "Quiz"): Unigram statistics often fail because high-frequency English letters (E, T, A, O) may not appear at all, or rare letters (Z, J, X) dominate due to sample variance.
    • Language / Domain Mismatch: If the plaintext is in another language (e.g. Italian or German), contains technical jargon, numbers, or is a lipogram (text deliberately omitting 'E'), the corpus model diverges.
  • Optional — Comparison of Alternative Approaches:
    • Simple Letter-Frequency (Argmax → 'E'): Maps the single most frequent ciphertext letter to 'E'. Extremely fast, but brittle on short/medium texts where 'T', 'A', or 'I' randomly outnumber 'E' (see the 19-char benchmark row above!).
    • N-Gram Scoring (Bigram Log-Likelihood): Scores candidate plaintexts via ∑ log P(cⱼ, cⱼ₊₁). Superior on short texts because impossible English transitions (like QZ or JX) heavily penalize wrong keys even when single-letter counts are noisy.
    • Exhaustive Key Search (Dictionary Verification): Generates all 26 shifts and checks word matches against a dictionary. Because |K| = 26, this succeeds even on a single 4-letter word like "JAZZ" where pure frequency analysis fails.

Discussion: ECC Attack vs. Caesar Attack, Real-World Scaling & Toy Flaws

  • Differences Between the ECC Attack and Statistical Caesar Cryptanalysis:
    • Target & Mechanism: The Caesar attack is a ciphertext-only statistical attack exploiting linguistic redundancy leaked into the ciphertext. The ECC attack is an algebraic public-key attack solving the Elliptic Curve Discrete Logarithm Problem (ECDLP, finding d from Q = dG) before touching the ciphertext.
    • Verification Criterion: Caesar cryptanalysis is probabilistic—every candidate shift produces letters, so we rely on a statistical score (χ²) to guess which output looks like English. The ECC attack is 100% deterministic and exact: as soon as d'G == Q holds mathematically, the exact private key is proven found, even if the encrypted message were random binary bytes.
  • Why This Attack Fails Against Properly Configured secp256k1:
    • In real Ethereum/Bitcoin secp256k1, the prime field is p ≈ 2²⁵⁶ and the generator order is n ≈ 1.158 × 10⁷⁷ ≈ 2²⁵⁶.
    • Linear Brute Force O(n): Requires up to 2²⁵⁶ curve additions—physically impossible even with planetary-scale computers over billions of years.
    • Generic Square-Root Algorithms O(√n) (Baby-Step Giant-Step / Pollard's Rho): Even the best classical ECDLP algorithms require √(2²⁵⁶) = 2¹²⁸ ≈ 3.4 × 10³⁸ operations (128-bit security level), and BSGS additionally requires O(2¹²⁸) memory storage, making key recovery computationally infeasible.
  • Optional — Restricted Key-Space Weaknesses vs. Intrinsic Toy Design Flaws:
    • Weaknesses from Restricted Key Space (p = 17, n = 18): Both the long-term private key d (from Q = dG) and any per-message ephemeral key k (from R = kG) can be recovered instantly via linear search, BSGS, or Pollard's Rho.
    • Weaknesses from Toy Scheme Design (even if p were 256-bit!):
      1. Single Fixed Ephemeral Key (k-Reuse / Deterministic Mode): If a toy implementation reuses the same ephemeral scalar k across characters or messages without proper key-stream chaining, identical masks are applied—turning ECC into a simple substitution/XOR cipher vulnerable to frequency analysis or two-time pad attacks (C₁ ⊕ C₂ = M₁ ⊕ M₂).
      2. Lack of Authenticated Encryption (Malleability): Because there is no MAC (unlike real ECIES which includes HMAC-SHA256), an active attacker can modify ciphertext bytes cᵢ in transit to flip predictable characters in the decrypted plaintext (Chosen-Ciphertext vulnerability).
      3. Un-hashed Coordinate Masking: Using raw curve coordinates (S.x, S.y) directly instead of passing them through a cryptographic Key Derivation Function (KDF / SHA-256) leaks algebraic structure from the elliptic curve group.
