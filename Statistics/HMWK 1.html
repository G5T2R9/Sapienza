3. Discussion: One-Way Function (ECDLP) vs. Cryptographic Hash Function

  • Properties meaningful for an ECC One-Way Function (Q = kG):
    • Determinism & Efficiency: Computing Q = kG is fast (using point addition / doubling).
    • Pre-image Resistance (ECDLP): Given Q and G, finding the scalar k is computationally infeasible for large primes (256-bit in Ethereum).
    • Algebraic Homomorphism: (k₁ + k₂)G = k₁G + k₂G. Unlike hashes, we need this mathematical structure so public keys can be used for digital signatures (ECDSA) and key exchange (ECDH).
  • Properties specific to Cryptographic Hash Functions (e.g., Keccak-256):
    • Uniform Bit Distribution & Domain: A hash function outputs uniformly distributed bitstrings across the entire output space. On an elliptic curve, only ~50% of x values have valid square roots mod p, and each valid x appears twice (for +y and -y mod p).
    • Strict Avalanche Criterion (SAC): Changing k → k+1 flips roughly ~50% of the coordinate bits on average, which looks similar to the avalanche effect. However, in ECC the next point is algebraically predictable ((k+1)G = kG + G), whereas in a hash function H(k+1) must be completely uncorrelated to H(k).
